## Agent skills

### Issue tracker

Issues and specs live as markdown files under `.scratch/<feature-slug>/` in this repo. See `docs/agents/issue-tracker.md`.

### Triage labels

Five triage roles, each label string equal to its role name (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), recorded as a `Status:` line in each issue file. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context layout: one `GLOSSARY.md` plus `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Git workflow

Fork layout: `origin` = the lazygophers fork (push target), `upstream` = `volcengine/OpenViking` (read-only source). `lazygophers` is the mainline branch; `main` exists only to mirror `upstream/main`.

- Sync upstream: `git fetch upstream`, merge `upstream/main` into `main`, then merge `main` into `lazygophers` — two merges, no rebase, no cherry-pick.
- Never switch branches in the main worktree (no `git checkout`/`git switch` there). All branch work happens in worktrees.
- Feature work: create a worktree from `lazygophers`: `git worktree add -b <branch-name> <repo-root>/.worktrees/<branch-name> lazygophers`. Develop and commit there.
- Merging a feature into `lazygophers`: run the merge in a worktree that has `lazygophers` checked out, not in the main worktree.
- Deleting a merged branch: `git branch -d` compares against the main worktree's HEAD and may refuse. Verify `git merge-base --is-ancestor <branch> lazygophers`, then use `git branch -D <branch>`. Remove the worktree first (`git worktree remove`).
- Do not develop on `main` or merge features into it; `main` only receives `upstream/main`.

## Build and test gotchas

- Bot tests need the Makefile's `uv sync --extra dev --extra test --extra bot --group build`. Plain `uv run --extra test pytest` in `bot/` fails with `ModuleNotFoundError: prompt_toolkit`.
- To validate `make run` while another server holds ports 14002/18790, pass `OV_RUN_PORT` / `OV_RUN_BOT_PORT`.
- `openviking/system_assets/manifest.json` sha256 is regenerated by builds. Commit it only when it matches the current content (`scripts/build_support/system_assets_manifest.py`); a stale hash breaks the runtime comparison in `openviking/system_assets/sync.py`.
